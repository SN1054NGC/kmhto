# KMHTO — учёт и планирование ТО/КМХ метрологического оборудования

Веб-приложение для работы с графиком технического обслуживания (ТО) и метрологических
работ (КМХ) средств измерений. Загружает Excel-график, разбирает его по месяцам,
показывает календарь и таблицу, позволяет переносить работы, планировать по интервалу,
вести карточки поверки/калибровки (с поиском в ФГИС «Аршин») — и работать
**несколькими людьми одновременно** через сервер-арбитр.

Приложение автономно: без сервера работает как локальный инструмент, все правки
хранятся в браузере.

## Быстрый старт

Требуется **Node.js 22+** (используется встроенный `node:sqlite`). `npm install`
не нужен — внешних зависимостей у проекта нет.

```powershell
cd C:\aila\KMHTO

# 1. один раз — администратор
node server/adduser.js admin "СвойПароль" admin "Администратор"

# 2. запуск сервера (Ctrl+C — остановка)
node server/index.js
#   [KMHTO] сервер 1.0.0 слушает ws://127.0.0.1:8787
#   [KMHTO] данные: C:\aila\KMHTO\data

# 3. открыть приложение
#    http://127.0.0.1:8787/          ← отдаёт сам сервер (рекомендуется)
#    либо файл app_kmhto.html в браузере
```

В приложении: вкладка **«Сеть»** → адрес `ws://127.0.0.1:8787/ws`, логин, пароль →
**«Подключиться»**. Затем администратором один раз нажать
**«⬆ Загрузить расписание на сервер»** — сервер получит исходный график.

Остальные пользователи:

```powershell
node server/adduser.js alice "пароль" specialist "Алиса"
node server/adduser.js bob   "пароль" manager    "Боб"
node server/adduser.js vera  "пароль" viewer     "Вера"
```

## Возможности

**Импорт и разбор**
- загрузка `.xlsx` (выбор файла или перетаскивание), авторазбор при открытии;
- **автоопределение структуры**: строка заголовков, начало данных, колонки
  (№, код, наименование, место установки, первый месяц) — поддержаны многострочные
  шапки (названия / месяцы / «(число)»);
- объединённые ячейки разворачиваются; грязные данные нормализуются
  (`ТО-1(12)`, `то 1 — 12`, `14,\n20,2,`, лишние пробелы);
- отчёт опечаток: разбор идёт всегда, окно открывается **по кнопке**
  («Отчёт опечаток (N)»);
- нормы времени из листа-справочника, в том числе ссылка на **технологическую карту**.

**График**
- таблица «оборудование × 12 месяцев», строки — как в файле;
- фильтры: Объект, тип, поиск, быстрая кнопка **«Только ТО-3»**;
- подсветка Сб/Вс/праздников, дни недели в метках, ТО-3 жирным;
- **drag & drop** (ЛКМ) — перенос; **Shift + перетаскивание** — обмен видами ТО;
- **стрелки «откуда → куда»** для всех переносов и перестановок, с привязкой к году;
- метка `✎ Имя` — кто последним менял строку.

**Календарь года**
- 12 месяцев, метки работ, доп. выходные;
- отдельный блок дат **поверки/калибровки** из карточки (данные Аршина): `ПВ`, `КЛ`, `до ПВ`, `до КЛ`.

**Карточка оборудования** (ПКМ по строке или по записи)
- **✎ Изменить запись** — единое окно: вид работ, месяц, день, причина, удаление;
- **🗑 Удалить эту запись…** — прямой пункт в ПКМ по записи, с обязательной
  причиной (она попадает в «Журнал изменений»);
- **⏳ сколько дней до ближайшего ТО/КМХ** — бейдж в карточке оборудования и
  строка в «Деталях» (ближайшая дата от сегодня, прошедшие переносятся на
  следующий год);
- комментарии к дате, сведения, история переносов;
- **🧾 Поверка / калибровка / Аршин** — даты поверки и калибровки, сроки действия
  свидетельств, номер свидетельства, ссылка на ФГИС «Аршин», поиск по номеру и названию;
- **📄 Технологическая карта** — ссылка из листа норм или заданная вручную.

**Планирование и заявки**
- планирование по интервалу с допуском ± дней (сдвиг с выходного на рабочий);
- **правила планирования** (ПКМ → «🗓 Правила планирования / автоплан…»): вид работ,
  базовая дата, интервал, допуск; график строится автоматически на выбранный год и
  перестраивается при смене года, ручные записи сохраняются;
- **автопродолжение**: при смене года график продолжается от последней даты
  прошлого года с шагом интервала (допуск ±, по умолчанию 3 дня), а для каждого
  ТО/КМХ можно задать **ручную стартовую дату** на год в окне правил;
- **сдвиг с выходных** и выбор дней недели: галочка «сдвигать» + чипы
  **«только»** (подбирать в эти дни) и **«кроме»** (не ставить в эти дни) —
  и в правилах, и в разовом «Запланировать по интервалу»; **по умолчанию план
  не ставится на Пт/Сб/Вс** (разрешены Пн–Чт), это меняется галочками;
- формирование заявки на работы за период, выгрузка в `.doc`;
- экспорт графика обратно в Excel: **лист `1` — ТО, лист `3` — КМХ**,
  `data` — справочник; структура совпадает с исходным файлом (4 описательные
  колонки, месяцы с колонки E), поэтому файл снова читается авторазбором.

**Совместная работа**
- сервер-арбитр: операция + `baseVersion`, права роли, конфликты;
- очередь операций: правки без связи уходят автоматически при подключении
  (идемпотентность по `opId` — повтор не применяется дважды);
- **журнал изменений** — кто, когда, что (было → стало) и причина; виден всем сразу;
- presence (кто онлайн), контроль синхронизации («Проверить и подтянуть»);
- **управление пользователями (только админ)**: вкладка «Сеть» — список пользователей,
  добавление, назначение роли, смена пароля, удаление. Себя и последнего администратора
  удалить нельзя; роль и логин перечитываются при каждой проверке токена, поэтому
  смена роли и удаление действуют сразу.

## Роли и права

Роль берётся **только из подписанного токена** (её нельзя подделать из браузера).
Права заданы по видам операций, пороги меняются администратором и хранятся в БД.

| Роль | Приоритет | Что может |
|---|---|---|
| `viewer` | 0 | только чтение |
| `specialist` | 300 | добавление, перенос, смена вида, перестановка, комментарии, карточка |
| `manager` | 600 | то же + удаление, планирование, выходные |
| `admin` | 999 | всё + загрузка расписания и настройка ролей |

Если правка пришла с устаревшей версией: при **более высоком** приоритете она
применяется как `overridden`, иначе — конфликт и откат с сообщением автору.

## ФГИС «Аршин»

Используется внешний публичный интерфейс Росстандарта:

```
GET https://fgis.gost.ru/fundmetrology/eapi/vri?...      — поиск
GET https://fgis.gost.ru/fundmetrology/eapi/vri/<vri_id> — запись целиком
```

- **гибкий фильтр**: наименование типа СИ, заводской/серийный №, рег. № типа,
  № свидетельства, организация-поверитель, год, обозначение, сортировка;
  номера разбираются из названия по правилу «после `№` и до запятой» + заводской
  номер из карточки, часть полей предзаполняется из поверки;
- **«только действующие»** (отсекает истёкшие свидетельства) и мгновенный
  **«фильтр по найденному»** по уже полученному списку;
- порядок: **комбинированный запрос** (несколько условий сразу) → **точное**
  совпадение по номеру → нечёткое → рег. № типа → свидетельство → обозначение →
  организация → название;
- запросы идут **через сервер** (в браузере — CORS, плюс Росстандарт ограничивает
  частоту и блокирует зарубежные IP/VPN): пауза 1,2 с, таймаут 20 с, кэш 10 минут;
- маршруты требуют токен: `GET /arshin/search`, `GET /arshin/record`;
- кнопки **«Открыть запись»** и **«Поиск в Аршине»**, кнопка **«Взять данные»**
  подставляет даты, № свидетельства и ссылку;
- перекрёстный поиск: найденная поверка сопоставляется с оборудованием графика
  («↔ в графике: …»), кнопка **«Показать в графике»** прокручивает к строке.

## Данные

Входной файл: лист `1` — график ТО (`ТО-1 (15)`), лист `3` — дни КМХ,
лист справочника (в тестовом файле — `коды`) — нормы, ТК, данные для поверки.

Идентификатор оборудования **стабильный**: «код + заводской номер», если номера нет —
«код + № п/п». Хранятся также `legacyId` (прежняя схема) и `version` (версия правок).
Старые сохранения мигрируют на новые идентификаторы автоматически.

Хранение: браузер (`localStorage`) — расписание, журнал изменений, очередь операций,
настройки, ширина колонок; сервер (SQLite `data/collab.db`) — эталонное состояние,
журнал операций, праздники, настройки ролей.

## Проверка проекта

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools\check.ps1
```

Проверяет целостность `app_kmhto.html` (теги, окончания строк, `node --check`),
синтаксис модулей сервера и прогоняет **17 наборов тестов**: парсинг и нормализация,
ТО/КМХ, переносы и перестановки, удаление, планирование, персистентность, экспорт,
идентификаторы и операции, сервер (56 проверок), клиент↔сервер (60),
ФГИС «Аршин» (53), структура и нормы, дни до ближайшего ТО/КМХ.

## Ограничения

- Для ФГИС «Аршин» нужен доступ с российского IP (VPN Росстандарт блокирует).
- Кнопка «Загрузить расписание на сервер» **перезаписывает** состояние сервера —
  это доступно администратору и делается осознанно.
- На хостинге сервер работает за Apache + Passenger (HTTPS терминируется там же);
  при локальном запуске шифрования нет — это режим для localhost и доверенной сети.
- Если прокси хостинга не туннелирует WebSocket, приложение автоматически
  переходит на HTTP-опрос (`/api/msg`, `/api/events`) — совместная работа сохраняется.
