# Отчёт о проекте KMHTO

**Приложение:** учёт, планирование и контроль ТО/КМХ метрологического оборудования
**Основной файл:** `app_kmhto.html` — веб-приложение в одном файле (без сборки)
**Сервер:** `server/` — Node.js, без внешних зависимостей
**Проверка проекта:** `tools/check.ps1` — целостность файла и 17 наборов автотестов

---

## 1. Назначение

Приложение ведёт график технического обслуживания (ТО) и метрологических работ
(КМХ) средств измерений: читает Excel-график, показывает календарь и таблицу,
позволяет переносить и планировать работы, вести карточки поверки/калибровки
с поиском в ФГИС «Аршин» и работать несколькими людьми одновременно через
сервер-арбитр.

Автономность: без сервера приложение работает как локальный инструмент, все
правки хранятся в браузере. С сервером — общее состояние, роли и журнал изменений.

## 2. Источник данных

Образец: `TOKMHver5.xlsx` (тестовые данные).

| Лист | Назначение | Структура |
|---|---|---|
| `1` | график ТО | № п/п, код СИ/оборуд., наименование, место установки, январь…декабрь; в ячейках месяцев виды ТО (`ТО-1 (день)`, `ТО-3 (день)`) |
| `3` | график КМХ / дат | те же столбцы; в ячейках месяцев — дни (числа), возможно несколько в одной ячейке |
| `data` | справочник оборудования | код, наименование, работы при ТО-1/ТО-2/ТО-3, нормы, ссылка на техкарту |

### 2.1. Семантика

- колонка = месяц, ячейка = список дней, строка = вид работ (ТО-1 / ТО-2 / ТО-3 / КМХ);
- ТО и КМХ — разные графики, в планировании участвуют совместно;
- в поле **«Объект»** попадает значение из колонки «Место установки» **дословно** —
  без сокращений и подстановок.

### 2.2. Обработка «грязных» данных

Переносы строк внутри ячейки, смешанные разделители (запятая, точка с запятой,
слэш, перенос), хвостовые разделители, лишние пробелы, мягкие переносы, похожие
кириллические и латинские символы, объединённые ячейки и разрывы строк,
недопустимые значения (день 0 или > 31).

## 3. Реализованный функционал

### 3.1. Импорт и разбор

- загрузка `.xlsx` (выбор файла или перетаскивание), авторазбор при открытии;
- автоопределение структуры: строка заголовков, начало данных, колонки
  (№, код, наименование, место установки, первый месяц), многострочные шапки;
- объединённые ячейки разворачиваются, значения нормализуются;
- **отчёт опечаток**: разбор идёт всегда, окно открывается по кнопке;
- нормы времени из листа-справочника, включая ссылку на технологическую карту.

### 3.2. График

- таблица «оборудование × 12 месяцев», порядок строк — как в файле;
- фильтры: объект, тип, поиск, быстрая кнопка «Только ТО-3»;
- подсветка Сб/Вс и праздников, дни недели в метках, ТО-3 жирным;
- **drag & drop** (ЛКМ) — перенос; **Shift + перетаскивание** — обмен видами ТО;
- **стрелки «откуда → куда»** для переносов и перестановок с привязкой к году;
- метка «кто последним менял строку».

### 3.3. Календарь года

- 12 месяцев, метки работ, дополнительные выходные;
- блок дат поверки и калибровки из карточки: `ПВ`, `КЛ`, «до ПВ», «до КЛ».

### 3.4. Контекстное меню (ПКМ)

Единое меню по строке оборудования и по записи графика: изменить запись, удалить
запись (с обязательной причиной), запланировать по интервалу, правила планирования
и автоплан, карточка оборудования, технологическая карта, комментарии.

### 3.5. Планирование

- планирование по интервалу в днях с допуском ± (окно проведения);
- **правила планирования**: вид работ, базовая дата, интервал, допуск; график
  строится на выбранный год и перестраивается при смене года, ручные записи
  сохраняются;
- **автопродолжение**: при смене года график продолжается от последней даты
  прошлого года с шагом интервала (допуск ±, по умолчанию 3 дня); для каждого
  вида работ можно задать ручную стартовую дату на год;
- **сдвиг с выходных** и выбор дней недели: чипы «только» (подбирать в эти дни) и
  «кроме» (не ставить в эти дни); по умолчанию план не ставится на Пт/Сб/Вс;
- бейдж **«сколько дней до ближайшего ТО/КМХ»** в карточке и в деталях записи
  (ближайшая дата от сегодня, прошедшие переносятся на следующий год).

### 3.6. КМХ, поверка и калибровка

Отдельный ввод данных по поверке и калибровке, сроки действия свидетельств,
номер свидетельства, вывод в одном листе, выгрузка данных по оборудованию.

### 3.7. ФГИС «Аршин»

- внешний публичный интерфейс Росстандарта: поиск `eapi/vri` и запись `eapi/vri/<id>`;
- гибкий фильтр: наименование типа СИ, заводской/серийный №, рег. № типа,
  № свидетельства, организация-поверитель, год, обозначение, сортировка;
- номера разбираются из названия по правилу «после № и до запятой», часть полей
  предзаполняется из карточки поверки;
- «только действующие» и фильтр по уже полученному списку;
- порядок поиска: комбинированный запрос → точное совпадение по номеру → нечёткое
  → рег. № типа → свидетельство → обозначение → организация → название;
- запросы идут через сервер (CORS и ограничение частоты у Росстандарта): пауза
  1,2 с, таймаут 20 с, кэш 10 минут; маршруты `GET /arshin/search`, `GET /arshin/record`
  требуют токен;
- перекрёстный поиск: найденная поверка сопоставляется с оборудованием графика.

### 3.8. Заявки и экспорт

- формирование заявки на работы за период, выгрузка в `.doc`;
- экспорт графика в Excel: лист `1` — ТО, лист `3` — КМХ, `data` — справочник;
  структура совпадает с исходным файлом (4 описательные колонки, месяцы с колонки E),
  поэтому выгруженный файл снова читается авторазбором.

### 3.9. Персистенция

Браузер (`localStorage`): расписание, журнал изменений, очередь операций, настройки,
ширина колонок. Сервер (SQLite `data/collab.db`): эталонное состояние, журнал
операций, праздники, настройки ролей.

Идентификатор оборудования стабильный: «код + заводской номер», при отсутствии
номера — «код + № п/п»; хранятся `legacyId` (прежняя схема) и `version` (версия
правок); старые сохранения мигрируют автоматически.

### 3.10. Оформление и масштабирование

Светлая нейтральная тема с системным шрифтом, адаптивная сетка, масштабирование
Ctrl +/−/0, окна диалогов корректно пересчитывают высоту и позицию кнопок при
любом масштабе.

## 4. Совместная работа

### 4.1. Стек и хранилище

Node.js без внешних зависимостей: встроенный `node:sqlite` (`DatabaseSync`) и
собственная реализация WebSocket (RFC 6455) в `server/ws.js`.

### 4.2. Протокол

Клиент входит через `POST /login` и получает подписанный токен (TTL 12 часов).
Далее каждая правка — **операция** с `opId` и `baseVersion`; сервер арбитрирует,
применяет и рассылает всем. Повторная отправка той же операции не применяется
дважды (идемпотентность по `opId`).

### 4.3. Транспорты

- **WebSocket** `GET /ws` — основной режим: подписка на события, presence, операции;
- **HTTP-опрос**: `POST /api/msg` (отправка сообщения, ответ в `replies`) и
  `GET /api/events?since=N` (длинный опрос до 25 с). Используется автоматически,
  если WebSocket недоступен (прокси не туннелирует соединение) — клиент определяет
  это сам и переключается без участия пользователя.

### 4.4. Роли и права

Роль берётся только из подписанного токена. Права заданы по видам операций,
пороги меняются администратором и хранятся в БД.

| Роль | Приоритет | Что может |
|---|---|---|
| `viewer` | 0 | только чтение |
| `specialist` | 300 | добавление, перенос, смена вида, перестановка, комментарии, карточка |
| `manager` | 600 | то же + удаление, планирование, выходные |
| `admin` | 999 | всё + загрузка расписания и настройка ролей |

Если правка пришла с устаревшей версией: при более высоком приоритете она
применяется как `overridden`, иначе — конфликт и откат с сообщением автору.

### 4.5. Офлайн-очередь и журнал изменений

Правки без связи складываются в очередь и уходят автоматически при подключении.
Журнал изменений показывает, кто, когда, что (было → стало) и причину — виден
всем участникам сразу. Есть presence (кто онлайн) и контроль синхронизации
(«Проверить и подтянуть»).

## 5. Структура проекта

    app_kmhto.html        всё приложение (разметка, стили, логика, сетевой слой)
    app.js                точка входа для Passenger (запускает server/index.js)
    server/               сервер совместной работы
      index.js            маршруты, обработка сообщений, арбитраж, HTTP-транспорт
      ws.js               WebSocket (RFC 6455) без зависимостей
      auth.js             пользователи, токены
      roles.js            роли и права по операциям
      model.js            модель графика, правила планирования, генерация
      store.js            SQLite: состояние, журнал операций, настройки
      arshin.js           клиент ФГИС «Аршин» (кэш, пауза, таймауты)
      config.js           настройки из переменных окружения
      adduser.js          создание/обновление пользователя
    vendor/               Bootstrap, иконки, SheetJS, FileSaver (локально, без CDN)
    tools/                проверка и автотесты
    deploy/               развёртывание (Jino, systemd, nginx, архивы)
    TZ.md, README.md      задание и описание проекта

## 6. Тесты и проверка целостности

    powershell -NoProfile -ExecutionPolicy Bypass -File tools\check.ps1

Проверка контролирует целостность `app_kmhto.html` (закрывающий тег, 4 тега
`<script>`, отсутствие «одиночных» LF, `node --check` для скриптов), синтаксис
модулей сервера и прогоняет **17 наборов тестов**: разбор и нормализация,
ТО/КМХ, переносы и перестановки, удаление, планирование, персистенция, экспорт,
идентификаторы и операции, сервер (56 проверок), клиент↔сервер (60),
ФГИС «Аршин» (53), структура и нормы, дни до ближайшего ТО/КМХ.

## 7. Развёртывание

Рабочая конфигурация — `kmhto.ru` на хостинге Jino: Apache + Phusion Passenger,
Node.js 22, приложение и API на одном домене (`/`, `/health`, `/login`, `/arshin/*`,
`/ws`, `/api/*`). Подробности, команды и диагностика — в `deploy/SERVER-STEPS.md`,
краткая сводка — в `deploy/DEPLOYED.md`.

## 8. Правила работы с файлом

- `app_kmhto.html` — один файл; переводы строк CRLF, 4 тега `<script>`;
- после любой правки: `tools/check.ps1` должен показать «ВСЁ В ПОРЯДКЕ»;
- каталог `data/` содержит рабочее состояние сервера и в репозиторий не попадает.

## 9. Локальный запуск

    node server/adduser.js admin "СвойПароль" admin "Администратор"
    node server/index.js
    # открыть http://127.0.0.1:8787/

В приложении: вкладка «Сеть» → адрес `ws://127.0.0.1:8787/ws` → логин и пароль →
«Подключиться». Администратор один раз нажимает «⬆ Загрузить расписание на сервер».
